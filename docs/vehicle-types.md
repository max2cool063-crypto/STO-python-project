# Тип ТС в карточке автомобиля

Тип (`CAR` — легковой, `TRUCK` — грузовой) хранится в `Car`, а не в `CarModel`.
Клиент выбирает его при добавлении автомобиля в личном кабинете. Сотрудник
выбирает тип нового автомобиля при создании записи.

Сотрудник может исправить госномер, VIN и тип автомобиля в разделе «Клиенты»
или кнопкой «Редактировать автомобиль» рядом с выбранным автомобилем в новой
записи. Доступны только активные автомобили, имеющие обращения на эту станцию;
владельца и модель эта форма не меняет. Карточка общая для клиента и станций.

Новая запись занимает один базовый слот для легкового автомобиля и два для
грузового. Изменение карточки не меняет сохранённые интервалы записей, включая
обычное сохранение заметок/статуса. При сохранении через форму редактирования
записи или переносе времени длительность пересчитывается по текущему типу,
проверяются расписание, блокировки и пересечения. Изменение интервала фиксируется
в журнале записи и сбрасывает актуальность прежних напоминаний.

## Обновление существующей установки

Перед обновлением сделайте резервную копию базы. Остановите старые процессы
приложения на время миграции: старый код использует удаляемое поле модели.
Миграция `0029_car_vehicle_type` переносит прежние значения в **все** автомобили,
включая неактивные, затем удаляет поле из моделей. Уже созданные записи не меняются.
В Docker Compose миграции выполняет сервис `migrate` при запуске новой сборки.
Перенесённые спорные классификации необходимо проверить в карточках автомобилей.

После появления разных типов у автомобилей одной модели откат к старой схеме
не может сохранить эти различия. Для возврата используйте резервную копию,
сделанную до обновления, вместе с соответствующей версией приложения.

## Начальный справочник

`booking/fixtures/cars.json` — предоставленный пользователем справочник из
84 марок и 714 моделей, адаптированный к новой схеме: удалён только `vehicle_type`
у моделей, названия и идентификаторы сохранены.

Для **пустого справочника** после миграций:

```sh
docker compose run --rm web python manage.py loaddata cars
```

Не загружайте fixture с фиксированными PK поверх собственного заполненного
справочника: совпавшие PK могут изменить смысл существующих связей.
Старые JSON с `vehicle_type` у моделей больше не подходят для прямого `loaddata`.
Исходный файл пользователя не изменён.
