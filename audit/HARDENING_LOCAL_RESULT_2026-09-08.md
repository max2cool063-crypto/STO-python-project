# Результат локального укрепления перед выпуском

Ветка: `feature/production-hardening`. Изменения относительно `d8935c2` пока локальные,
без коммита и отправки в удалённый репозиторий. Текущий origin — GitHub; для GitLab
потребуется настроить соответствующий remote. Секреты SMTP не читались и не изменялись.

## Выполнено

1. Добавлена общая проверка дат/времени и полей пользователей до обращения к БД.
   Длинный email новой регистрации отклоняется без HTTP 500; существующие аккаунты
   с длинным email сохраняют возможность запросить ссылку установки пароля.
   Допустимые символы email не ограничиваются регулярным выражением username.
   Неверные даты корректно обрабатываются в клиентской и станционной записи,
   переносах, блокировках, расписании и API слотов.
2. Добавлены три PostgreSQL-теста реальных конкурентных HTTP-запросов. Тест дожидается
   ожидания блокировки обоими соединениями в pg_stat_activity, затем отпускает её.
   Проверяются одинаковый слот, запись одновременно с блокировкой, перенос
   одновременно с отменой. Перенос и напоминания блокируют только Appointment,
   без лишних блокировок связанных таблиц. Ожидаемый конфликт слота больше не
   журналируется как авария приложения.
3. Выполнена сборка Dockerfile с установкой зависимостей из requirements.txt.
   Собран окончательный образ `sto-hardening-final:local` со всеми изменениями.
   Shell-скрипты нормализованы в LF; добавлен .gitattributes.
   Backup/restore smoke test использует уникальный Compose-проект, собственные
   volume, отключённую внешнюю почту и не публикует порт. Создаёт реальную запись,
   автомобиль и PNG-фото, изменяет данные, восстанавливает backup и проверяет
   связи БД, точные байты изображения и защищённую выдачу фото после входа.
4. Добавлено журналирование ошибок почтового backend, нулевой доставки,
   неудачных напоминаний и внутренних уведомлений. Для SMTP не выводятся адреса,
   содержимое письма или текст исключения. Новая команда run_maintenance пишет
   начало, завершение, длительность и ошибки каждой фоновой задачи. При сбое первой
   задача отправки напоминаний всё равно запускается; итоговый код ненулевой.
   Compose использует эту команду. Добавлены тесты отказа SMTP и повторной попытки.

## Что не входит в результат

Реальная SMTP-доставка была проверена пользователем ранее. Автоматические проверки
использовали изолированные/подменённые backend и не отправляли внешних писем.
Надёжная очередь обычных подтверждений пока не реализована; повторные попытки
напоминаний возможны только внутри текущего окна отправки. SMTP-вызов напоминания
по-прежнему выполняется под блокировкой самой записи для защиты от параллельных запусков.
Сбор журналов и внешние оповещения об ошибках нужно настроить на сервере.
Два прежних предупреждения collectstatic о дубликатах JS Django/Jazzmin остаются.
HTTPS через настоящий reverse proxy и production-домен проверяется при развёртывании.

Команды повторной проверки и описание журналов добавлены в README.md.
